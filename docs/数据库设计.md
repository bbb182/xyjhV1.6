# 星语计划 · 数据库设计

> 适用版本：V1.4 及以后
> 技术选型：**SQLite 3**（Node.js 内置 `node:sqlite`，**零依赖、免安装**）
> 入口：`db/schema.sql` · `db/db.js` · `db/seed.js` · `db/repo.js` · `server.js`

---

## 一、为什么这样设计

项目原本是纯静态站点：所有内容集中在 `js/data.js`，页面直接读取 `window.XINGYU`，
购物车用 localStorage，后台订单与资金流水是写死在 `js/admin.js` 里的演示数组。

引入数据库后按「**记录**」与「**文案**」两类拆分：

| 类别 | 存放位置 | 理由 |
|---|---|---|
| **记录型**：学生档案、成长记录、作品、订单、资金流水、报名申请、披露报告、月度账目 | **数据库** | 会持续新增、需要统计与状态流转，且要支持后台增删改 |
| **文案型**：站点信息、导航、分类、理念卡、闭环步骤、统计口径、团队顾问、表单选项 | 仍留在 `js/data.js` | 属于编辑内容，改文案不需要动库，延续「改内容只动一个文件」的约定 |

这样既保留了原来的维护手感，又让业务数据真正落库。

## 二、实体关系

```text
students 1 ──── n milestones          学生 → 成长记录（一人一档时间轴）
students 1 ──── n works               学生 → 作品
works    1 ──── n work_features       作品 → 工艺特性（逐条）
orders   1 ──── n order_items         订单 → 明细（下单时快照标题与单价）
works    1 ──── n order_items         作品 → 明细（用于销量统计与库存扣减）

（独立表）
fund_records          资金流水（收入 / 支出）
applications          报名与合作申请
disclosure_reports    季度 / 年度披露报告
monthly_ledger        月度收支账目（公益公开页使用）
```

## 三、表结构

### 1. `students` 学生档案

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | `s1`、`s2`… 与前端引用一致 |
| `nick` | TEXT NOT NULL | 展示用姓名（已获监护人授权） |
| `age` | INTEGER | 6–30（CHECK 约束） |
| `city` | TEXT | 城市，当前统一「太原」 |
| `direction` | TEXT | 兴趣方向，如「掐丝珐琅 · 取丝与弯折」 |
| `quote` / `bio` | TEXT | 一句话与简介 |
| `tags` | TEXT | JSON 数组字符串，如 `["掐丝珐琅","银杏"]` |
| `avatar` / `c1` / `c2` | TEXT | 头像与卡片配色 |
| `status` | TEXT | `active` / `graduated` |
| `sort_no` | INTEGER | 保持 `data.js` 的编辑顺序 |

### 2. `milestones` 成长记录

| 字段 | 类型 | 说明 |
|---|---|---|
| `student_id` | TEXT FK→students | 级联删除 |
| `occurred_on` | TEXT | `2026.01` 形式 |
| `title` / `description` | TEXT | 事件与描述 |
| `sort_no` | INTEGER | 时间轴顺序 |

### 3. `works` 作品

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | `w01`、`w02`… |
| `student_id` | TEXT FK→students | `ON DELETE RESTRICT`，防止误删有作品的作者 |
| `category` | TEXT | `intangible` / `culture` / `collection` |
| `price` / `original_price` | REAL | 单位：元，`price >= 0` |
| `stock` / `sales` / `likes` | INTEGER | 库存、销量、收藏，均非负 |
| `cover` | TEXT | 相对路径 `images/works/...` |
| `story_why` / `story_how` / `story_meaning` | TEXT | 创作故事三段，前端拼成 `story` 对象 |
| `status` | TEXT | `on` 上架 / `off` 下架 |
| `sort_no` | INTEGER | 首页取前 6 件依赖此顺序 |

### 4. `work_features` 作品特性

`work_id` FK→works（级联删除）、`content`、`sort_no`，一行一条工艺说明。

### 5. `orders` / `order_items` 订单

| `orders` 字段 | 说明 |
|---|---|
| `order_no` | 唯一，格式 `XY` + `YYYYMMDD` + 三位序号，由 `repo.createOrder` 生成 |
| `buyer_name` / `buyer_contact` | 买家信息 |
| `amount` | 金额，**由服务端按数据库单价重算**，不信任前端传值 |
| `status` | `待发货` / `已发货` / `已完成` / `退款中` |

`order_items` 保存 `title`、`unit_price`、`qty` 快照：作品改价后历史订单金额不受影响。

### 6. `fund_records` 资金流水

`occurred_on`、`type`（`income` / `expense`，CHECK 约束）、`item`、`amount`（恒为正，方向由 `type` 决定）、`status`、`note`。

### 7. `applications` 报名与合作申请

`name`、`contact`（必填）、`type`、`org`、`message`、`status`（`待审核` / `已通过` / `已拒绝`）。

### 8. `disclosure_reports` 披露报告

`name`、`period`、`audit_status`（`已发布` / `整理中`）、`published_on`。

### 9. `monthly_ledger` 月度账目

以 `month` 为主键（如 `2026 年 5 月`），存数值型 `income` / `expense` / `balance`，由接口格式化后给前端。

## 四、数据流

```text
        js/data.js（文案配置，唯一来源）
                 │
   db/seed.js ───┤ 读取并导入「记录型」数据
                 ▼
            SQLite (db/xingyu.db)
                 │  db/repo.js 把行映射成与 data.js 同构的对象
                 ▼
        GET /api/bootstrap
                 │
   js/api.js（同步取回并覆盖 window.XINGYU）
                 ▼
   main.js / home.js / works.js / mall.js / admin.js（无需改动即可消费）
```

**离线回退**：`js/api.js` 只在 `http(s)` 下请求接口；直接双击 HTML（`file://`）或部署在纯静态托管上时，接口不可用 → 静默保留 `js/data.js`，站点功能完全不变。

## 五、接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查：库路径、各表行数 |
| GET | `/api/bootstrap` | 全站渲染数据（文案配置 + 作品 + 学生 + 月度账目） |
| GET | `/api/works?category=&q=&sort=&limit=` | 作品列表（`sort`：`priceAsc` / `priceDesc` / `sales` / `latest`） |
| GET | `/api/works/:id` | 作品详情（含特性） |
| GET | `/api/students` / `/api/students/:id` | 学生档案（含成长记录） |
| GET | `/api/orders?status=&limit=` | 订单列表（后台） |
| GET | `/api/orders/:orderNo` | 单张订单 + 明细 + 30% 捐赠额 + 受助编号 + 证书号（爱心证书查询） |
| POST | `/api/orders` | 创建订单，`{ items:[{id,qty}], buyerName?, buyerContact? }` |
| PATCH | `/api/orders/:orderNo` | 修改订单状态，`{ status }` |
| GET | `/api/funds?limit=` | 资金流水 + 收支汇总 |
| GET/POST | `/api/applications` | 申请列表 / 提交申请 |
| PATCH | `/api/applications/:id` | 审核申请，`{ status }` |
| GET | `/api/reports` | 披露报告 |
| GET | `/api/monthly` | 月度账目 |
| GET | `/api/dashboard` | 后台汇总（在售数、待审申请、本月销售额、资金） |

错误统一返回 `{ "error": "说明" }`，状态码 400 / 404 / 413 / 500。

## 六、使用方式

```bash
# 1. 导入初始数据（幂等，可反复执行；--reset 先清空）
node db/seed.js
node db/seed.js --reset

# 2. 启动（空库会自动导入）
node server.js
#   → http://localhost:8080/         站点
#   → http://localhost:8080/api/health

# 3. 仅改文案：编辑 js/data.js 后重启服务（静态文案有 mtime 缓存，重启即生效）
```

环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `XY_PORT` | `8080` | 端口 |
| `XY_DB` | `db/xingyu.db` | 库文件路径 |
| `XY_DB_READONLY=1` | 关闭 | 只读模式，演示部署时锁定数据 |

## 七、约定与注意事项

1. **金额**：库内为 `REAL`（元），接口输出为 `¥1,234` 字符串，同时保留 `amountValue` / `incomeValue` 等数值字段供计算。
2. **排序**：`works.sort_no` / `students.sort_no` 固定抓取 `data.js` 的数组顺序，保证首页「前 6 件」和故事区顺序不因日期变化而漂移。
3. **一致性**：`repo.createOrder` 在事务内校验库存 → 生成订单 → 扣库存 / 加销量，任一步失败整体回滚。
4. **安全**：`/db/` 目录与 `*.db` 文件禁止通过 HTTP 访问；接口当前**未做鉴权**，仅适用于本地演示，公网部署前必须加登录与权限控制（详见第八节）。
5. **密码/密钥**：当前无用户体系，未存储任何凭据。
6. **迁移到 MySQL**：`db/repo.js` 是唯一的数据访问出口，表结构可直接映射；需替换的只有 `db/db.js` 的连接层与自增语法（`AUTOINCREMENT` → `AUTO_INCREMENT`）、`datetime('now','localtime')`（→ `NOW()`）。

## 九、数据在页面上的呈现（对照表）

| 库表 | 展示页面 | 展示形式 | 状态 |
|---|---|---|---|
| `works` | 首页 / 作品展示 / 公益商城 / 作品详情 | 作品卡、详情大图、价格与销量 | 已有 |
| `students` + `milestones` | 星星故事 / 作品详情 | 学生卡 + 成长时间轴 | 已有 |
| `work_features` | 作品详情 | 工艺特点列表 | 已有 |
| `orders` + `order_items` | 管理后台「订单管理」 | 表格（订单号、商品、金额、状态） | 已有 |
| `fund_records` | **公益公开页「资金流水」** + 后台 | 收支汇总卡（4）+ 逐笔明细表 | **本次新增** |
| `monthly_ledger` | **公益公开页「月度收支趋势」** | 收入/支出双柱图（按最大值等比）+ 明细表 | **本次新增** |
| `disclosure_reports` | **公益公开页「披露报告」** + 后台 | 报告卡片 + 已发布/整理中徽章 | **本次新增** |
| `applications` | **管理后台「申请管理」** | 统计卡（待审/通过/拒绝/累计）+ 列表 + 通过/拒绝按钮 | **本次新增** |
| `orders`（单张） | **爱心证书查询页** | 证书卡：订单号、受助编号、明细、订单金额、30% 捐赠额、善款去向，可打印/存 PDF | **本次新增** |

页面与文件的对应：

- 公益公开：`public.html` + `js/public.js`（新增样式就地写在页面 `<style>` 中）
- 爱心证书：`certificate.html` + `js/certificate.js`，入口在页脚「爱心证书查询」与商城说明
- 后台申请：`admin.html` 的 `applications` 面板 + `js/admin.js`
- 数据接入：统一由 `js/api.js` 在页面加载前覆盖 `window.XINGYU` 与提供 `window.XYAPI`

展示形式的选择理由：

| 形式 | 用于 | 为什么 |
|---|---|---|
| 汇总卡 | 资金收支、申请计数 | 一眼看到关键数字，答辩时好讲 |
| 明细表 | 资金流水、订单 | 可逐条核对，体现「可追溯」 |
| 柱状趋势 | 月度收支 | 直观呈现收支平衡与波动 |
| 时间轴 | 成长记录 | 体现"一人一档"的过程感 |
| 徽章 | 订单状态、报告状态、申请状态 | 状态一眼可辨 |
| 证书卡 | 爱心证书 | 情感锚点 + 可打印的实体凭证 |
